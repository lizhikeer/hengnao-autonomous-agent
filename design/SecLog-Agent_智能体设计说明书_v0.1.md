# SecLog-Agent 智能体设计说明书

> **课题名称**：基于恒脑（安恒智能体开发平台）的自主智能体设计、构建和优化实践  
> **选题**：面向 SOC 运营的日志智能研判与响应编排智能体（SecLog-Agent）  
> **版本**：V0.1（初稿）  
> **日期**：2026-10-11

---

## 1. 概述

### 1.1 背景与目标

安全运营中心（SOC）一线分析师长期面临"告警疲劳"：海量日志噪声淹没有效告警，人工研判耗时长、经验难以沉淀。本课题基于安恒恒脑智能体开发平台，构建一个面向 SOC 场景的日志智能研判与响应编排智能体，实现**日志接入 → 智能研判 → 关联检索 → 邮件通知 → 人工确认处置**的完整业务闭环。

核心目标：

1. **跑通智能体**：构建真实可用、可演示的智能体，实现业务闭环；
2. **持续优化**：完成至少三轮有记录的优化迭代（问题 → 修改 → 实测效果）；
3. **经验沉淀**：形成可复用的智能体工程方法论。

### 1.2 角色设定与系统边界

**目标用户**：SOC 一线安全分析师（L1）、企事业单位安全运维工程师。

**系统角色**：具备高级安服工程经验的虚拟运营专家数字员工。

**系统边界**：

| 支持                           | 不支持                    |
| ---------------------------- | ---------------------- |
| Web 访问日志（Nginx/Apache/IIS）   | 底层二进制原始流量（PCAP）的在线组包还原 |
| 网络遥测日志（Zeek/Suricata 离线解析产物） | 无审批的全自动高危处置            |
| 主机认证日志（Linux secure/auditd）  | 跨租户、跨平台的外部系统直连         |
| 单条与批量日志的定性研判                 | 企业真实生产数据分析（合规红线）       |

高危处置动作（如 IP 阻断）**必须**经人工确认节点兜底，防范误杀导致业务中断。

## 2. 总体架构

系统采用"**恒脑云端编排 + NAS 私有化数据/工具底座**"的三层架构：

```
┌─────────────────────────────────────────────────────────┐
│  恒脑平台（gc.das-ai.com，云端 SaaS）                      │
│  开始节点 → 代码清洗 → 白名单分支 → LLM 研判(+RAG)         │
│    → HTTP 插件调用 → 结果组装 → 交互节点(人工确认) → 结束    │
└──────────────┬──────────────────────────────────────────┘
               │ HTTPS（公网可达，IPv4 兜底）
┌──────────────▼──────────────────────────────────────────┐
│  私有 NAS（Docker 容器化部署，Caddy 终结 TLS）              │
│  FastAPI 工具层 ── ClickHouse 日志库 ── SMTP 邮件服务       │
│  Zeek/Brimcap 离线解析 ── 仿真数据注入                     │
└───────────────────────────────────────────────────────────┘
```

**分层职责**：

- **平台层**：业务编排、大模型推理、知识库召回、人机协同、结构化输出；
- **工具层（FastAPI）**：日志检索、情报代理、邮件通知、处置执行的唯一出口，所有外部能力经强类型参数化接口暴露；
- **数据层（ClickHouse + Zeek）**：网络遥测日志的存储、预聚合与离线解析。

## 3. 平台工作流设计

### 3.1 节点拓扑

| #  | 节点   | 类型                | 职责                                                                     |
| -- | ---- | ----------------- | ---------------------------------------------------------------------- |
| 1  | 开始节点 | Start             | 接收 `raw_logs`（String）、`asset_context`（String）、`mode`（String：fast/deep） |
| 2  | 日志清洗 | Code (Python)     | 正则字段抽取、编码探针、不可见字符剥离、字段完整性校验                                            |
| 3  | 分流路由 | 条件分支              | 白名单流量 → 轻量放行；残缺日志 → 异常反问；可疑日志 → 深度研判                                   |
| 4  | 研判推理 | LLM               | CoT 三段式推理，挂载 RAG 知识库，Guided JSON 强约束输出                                 |
| 5  | 历史关联 | Plugin            | 调 `/api/tools/ip_summary` 查源 IP 历史行为画像                                 |
| 6  | 证据检索 | Plugin            | 调 `/api/tools/ip_recent_alerts` 拉取关联告警证据链                              |
| 7  | 结果组装 | Code              | Schema 校验、JSON 封装、置信度阈值判断（<0.6 强制人工介入）                                 |
| 8  | 邮件通知 | Plugin            | 高危/可疑结论调 `/notify_email` 发送研判报告                                        |
| 9  | 人工确认 | Interactive (模式B) | 高危处置前阻断等待确认（`confirm_block`，单选：是/否）                                    |
| 10 | 处置执行 | Plugin            | 确认后调 `/api/response/block_ip` 下发阻断                                     |
| 11 | 结束节点 | End               | Markdown 报告 + 结构化 `results`（供 Open API 消费）                             |

### 3.2 关键平台配置

- **Temperature ≤ 0.2**（研判场景），开启"思考"保留 CoT 思维链（兼作优化留痕素材）；
- **Guided JSON** 强约束输出，`required` 列表禁止为空；
- API 工具上线前必须在平台**调试通过（HTTP 200）**，否则节点置灰不可选；
- 智能体须**发布**后获得 `agent_id`，方可被 Open API / 子智能体调用；
- 高危处置严禁模型直连阻断插件，必须前置交互节点。

## 4. 数据层设计（NAS）

### 4.1 流量解析与数据注入

- **离线解析**：Brimcap（单容器集成 Z*eek + Suricata）批处理 PCAP → NDJSON；*
- ***权威数据集****：CIC-IDS2017/2018，CSV 特征经映射脚本转换为 Zeek conn.log 规范 JSON 批量灌库；*
- ***仿真数据****：自研脚本生成脱敏攻击/正常混合日志（答辩主用数据源）；*
- ***合规红线****：严禁使用企业内网真实数据与客户流量*。

### 4.2 ClickHouse 存储设计

明细表 `sec_ops.network_events`：16 个归一化字段（timestamp / event_type / src_ip / dest_ip / proto / app_proto / duration / orig_bytes / resp_bytes / alert_signature / alert_category / alert_severity / http_uri / http_user_agent 等），MergeTree 按天分区。

预聚合物化视图 `mv_src_ip_hourly_stats`：以源 IP 为主键的 1 小时窗口统计（事件数、目标 IP 数、端口数、高危告警数、外发字节数），避免研判时全表扫描。

## 5. 工具层设计（FastAPI，NAS）

**设计原则**：强类型参数化 API（Pydantic 校验），**坚决不做开放式 Text-to-SQL**——防止模型生成方言错误 SQL、全表扫描 OOM 与注入风险。

| 端点                            | 方法   | 功能                       | 安全控制                                            |
| ----------------------------- | ---- | ------------------------ | ----------------------------------------------- |
| `/api/tools/ip_summary`       | GET  | 源 IP 历史行为画像（滑窗聚合）        | 参数校验、max_execution_time=5、行数上限                  |
| `/api/tools/ip_recent_alerts` | GET  | 关联告警证据链检索                | 同上                                              |
| `/api/tools/ip_enrich`        | GET  | 威胁情报代理（超时降级）             | 异常兜底返回空情报                                       |
| `/notify_email`               | POST | SMTP 研判报告邮件（复用 QQ 邮箱授权码） | 收件人白名单                                          |
| `/api/response/block_ip`      | POST | IP 阻断处置                  | **三重门禁**：HMAC 签名时效校验 + 基础设施硬白名单 + iptables 幂等下发 |

**阻断安全门禁**（防幻觉误杀）：核心网关、DNS、内网保留网段硬编码白名单不可绕过；命中白名单的阻断请求强制降级为"仅告警"。

## 6. 知识库设计（恒脑 RAG）

平台知识库原生支持"向量 + 关键词倒排"双通道召回，直接满足安全领域混合检索需求，无需自建向量引擎。

| 知识库         | 内容                                      | 切分策略                        |
| ----------- | --------------------------------------- | --------------------------- |
| ATT\&CK 战术库 | STIX 2.1 精选技战术（T1190/T1059/T1110 等）     | 对象级切分：单技术 = 单切片，紧凑 Markdown |
| CVE 处置卡片    | 高危漏洞描述 + CPE + CVSS + 缓解措施              | 单 CVE = 单条目（问答对库）           |
| WAF/处置规则库   | Nginx ACL / iptables / ModSecurity 基准规则 | 文本分块（512）                   |

## 7. 模型配置策略

- **首选**：自定义模型接入 DeepSeek（经 NAS new-api 中转，统一 key 管理与调用审计）；
- **兜底**：恒脑内置安全大模型（外部链路故障时无缝切换，保障答辩稳定性）;
- 研判节点 temperature ≤ 0.2，Max Tokens 按需调至 4096+。

---

## 8. 通知与处置闭环

1. 研判结论达 HIGH/CRITICAL → 组装节点打包 `{to, subject, body}` → `/notify_email`；
2. 邮件采用 Jinja2 渲染 HTML 报告：威胁等级徽章、攻击者/受害者实体、CoT 推理摘要、证据链时间线表格；
3. 处置双通道：
   - **平台内**：交互节点阻断，页面点击"是"后执行 `/block_ip`（验收红线路径）；
   - **邮件增强**：邮件内嵌审批链接，点击后经 FastAPI 调恒脑 Open API `/open/api/v2/agent/execute/resume` 恢复工作流（HMAC 签名 + 时效校验）。

---

## 9. 网络与部署方案

- 全部自建服务容器化部署于个人 NAS（Docker），Caddy 反代终结 TLS；
- **已知风险**：恒脑云端出口不支持 IPv6（已实测证实），NAS 仅公网 IPv6；
- **应对**：FastAPI 工具层经 **natfrp 穿透至 IPv4 节点**暴露公网地址；第 1 周完成平台 API 工具调试验证（HTTP 200）；
- 模型链路若走 NAS new-api 中转，同样须经 IPv4 兜底；否则直接使用平台内置模型。

## 10. 三轮迭代优化规划（留痕框架）

| 迭代    | 优化类别           | 暴露问题（复现案例）       | 修改内容                             | 预期效果             |
| ----- | -------------- | ---------------- | -------------------------------- | ---------------- |
| V0    | —              | MVP：单 LLM 节点极简拓扑 | 跑通基线，暴露缺陷                        | 建立 baseline      |
| V0→V1 | A 提示词 + D 格式约束 | 二次编码载荷漏报；输出格式漂移  | CoT 三段式 + Few-Shot + Guided JSON | 解码准确率↑，契约匹配 100% |

| V2→V3 | C 工具 + 知识库     | 无外部情报上下文；建议泛化    | 情报代理 + RAG 挂载 + SMTP 通知 + 人工确认阻断 | 完整闭环，企业级要求       |

每轮迭代第一时间记录：问题现象、修改假设、实测差异、决策判定——**过程留痕与最终可用同等权重**。

## 13. 风险登记

| 风险                  | 等级 | 应对                                   |
| ------------------- | -- | ------------------------------------ |
| 恒脑云端不支持 IPv6（已证实）   | 高  | natfrp IPv4 穿透，第 1 周验证               |
| 内置 MCP 工具可用性波动      | 中  | 关键路径用自建 HTTP 插件，MCP 仅作增强             |
| 模型输出幻觉/格式失效         | 中  | Guided JSON + 代码节点 Schema 校验 + 自纠错重试 |
| ClickHouse 恶意查询 OOM | 中  | 参数化 API + 物化视图 + 执行时限                |
| 误封核心资产              | 高  | 交互节点 + HMAC 门禁 + 硬白名单三重防线            |
| 全链路时延 10-30s        | 低  | fast 模式旁路，深度链路用于录屏                   |
