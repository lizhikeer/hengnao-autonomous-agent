# BGE 中文向量模型与混合检索方案

**本方案采用 bge-small-zh-v1.5 语义检索＋BM25 关键词检索，使用 RRF 合并排名。** 检索对象是安全知识卡、已审核的正确案例和纠错案例；检索结果供 Agent 选择查证步骤、参考历史经验。

## 1. 各部分

| 部分 | 采用组件 | 作用 |
| --- | --- | --- |
| 文本向量化 | bge-small-zh-v1.5 | 把调查问题和知识文本转换成表示语义的数字向量 |
| 语义检索 | Qdrant | 按向量相似程度，找到意思相近的知识 |
| 关键词检索 | SQLite FTS5 的 BM25 排名 | 按正文中的词项匹配，找到攻击术语、函数名和技术编号相关内容 |
| 结果合并 | 服务端 RRF | 综合两路结果的排名，形成统一候选列表 |

BGE 负责理解文本相似性，Qdrant 负责保存和查询向量。BM25 根据词项出现情况及文档长度排序；FTS5 是 SQLite 自带的全文检索组件，支持 BM25 排名。[SQLite 文档](https://www.sqlite.org/fts5.html)

关键词部分选择 FTS5，是为了复用项目已规划的 SQLite，减少新增服务；相应需要维护一份与向量索引对应的文本索引。

## 2. BGE 模型选型

采用 [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5)，输出 512 维中文语义向量。模型规模较小，适合当前中文知识卡的组织形式，同时控制计算和存储开销。

知识文本与调查问题均使用该模型编码。问题编码时添加中文检索前缀，知识正文直接编码；两端向量均进行归一化，用于相似度检索。

## 3. 知识文本内容

**语义文本**保留标题、适用现象、所需数据、判断条件和后续查证步骤。按 bge-small-zh-v1.5 的输入长度控制片段大小，用调查问题或规则标识关联片段；检索后补齐完整规则的前提、步骤及来源，供 Agent 连贯阅读。

**关键词文本**采用一致的中文分词和术语表，关联“SQL 注入／SQLi”“密码爆破／Brute Force”等别名。技术编号、接口路径等另保留原值，供精确匹配。

两路检索通过同一张卡片的编号和版本对应。审核状态、项目范围、有效期用于限定可检索内容；攻击术语和正文词项用于相关性排序。

## 4. 混合检索流程

1. **组织问题。** Agent 提供当前要查明的问题及已有线索，例如“请求含 UNION SELECT 且返回 200，怎样核查数据库数据是否被读出”。
2. **分别查找。** BGE 将问题向量化，由 Qdrant 查找语义相近的知识；关键词支路用“UNION SELECT”等词项，经 BM25 查找相关文本。两路使用一致的检索范围。
3. **合并排名。** RRF（倒数排名融合）按每条结果在两路列表中的名次综合排序。多路同时靠前的结果优先，单路命中的相关结果也能保留，再按卡片去重。
4. **返回调查材料。** 按所选规则补齐所需数据、判断条件、后续步骤、卡片版本与出处；纠错案例同时返回错误原因和正确做法。根据上下文长度选择完整条目交给 Agent。

RRF 使用名次合并，适合综合向量相似度和 BM25 这两种不同含义的分数；此处由服务端合并 Qdrant 与 FTS5 的结果。[混合检索与 RRF 说明](https://qdrant.tech/documentation/search/hybrid-queries/)

## 5. 这样设计的收益与代价

| 方面 | 对本项目的影响 |
| --- | --- |
| 语义检索 | “尝试很多次密码后终于登录”也能查找登录爆破相关知识，适应不同表述 |
| 关键词检索 | “UNION SELECT”“T1110”等术语能直接参与匹配，补充语义相似检索 |
| 两路合并 | 同时照顾调查问题的含义和具体技术线索，减少只依靠其中一路时遗漏相关知识的情况 |
| 维护代价 | 中文分词、术语别名需要维护；知识新增、更新和下架时，两份索引需要同步对应 |
