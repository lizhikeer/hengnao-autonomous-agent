# 智能体四维评测规则

按 `case_id` 对照场景标准答案。每题标注真值（恶意或正常）、证据是否足够、主要攻击阶段、涉及的资产或账号、关键调查事实及其日志编号，以及允许的处置动作、目标和授权条件。需要自动阻断的题目另标注阻断时限和预期结果。正式评测只向 Agent 提供可观察日志和业务上下文，人工阶段标签 `attack_stage_hint` 留给评测端。

| 维度 | 指标 | 公式 | 变量定义与判分条件 |
| --- | --- | --- | --- |
| 检测 | 检出率 | $\mathrm{TP}/N_{\mathrm{attack}}$ | $\mathrm{TP}$ 为正确判为恶意的场景数。$N_{\mathrm{attack}}$ 为全部恶意场景数。 |
| 检测 | 误报率 | $\mathrm{FP}/N_{\mathrm{normal}}$ | $\mathrm{FP}$ 为误判为恶意的正常场景数。$N_{\mathrm{normal}}$ 为全部正常场景数。 |
| 检测 | 弃权率 | $N_{\mathrm{abstain}}/N$ | $N_{\mathrm{abstain}}$ 为有效的 `insufficient_evidence` 输出数。$N$ 为全部场景数。 |
| 调查 | 诊断准确率 | $N_{\mathrm{correct}}/N_{\mathrm{diagnosable}}$ | $N_{\mathrm{diagnosable}}$ 为证据足够的场景数。$N_{\mathrm{correct}}$ 为其中恶意判定、主要攻击类型（按七类及登记别名匹配）和涉事实体均正确的场景数。 |
| 调查 | 关键事实得分（单题） | $F_{\mathrm{hit}}/F$ | $F$ 为标准答案的关键事实数。$F_{\mathrm{hit}}$ 为正确识别的事实数，如攻击是否成功、相关阶段及影响范围。每项最多计 1 分。 |
| 证据 | 关键证据覆盖率（单题） | $E_{\mathrm{covered}}/E$ | $E$ 为须举证的关键事实数。$E_{\mathrm{covered}}$ 为已提交的有效引用完整覆盖至少一组等价证据的事实数。新增等价证据由人工复核。 |
| 证据 | 无效引用数 | $\sum_{i=1}^{N} e_i$ | $e_i$ 为第 $i$ 题无效日志编号的去重计数。日志不存在、跨场景或本次查询未返回均属无效。 |
| 防御 | 处置正确率 | $A_{\mathrm{correct}}/A$ | $A$ 为有处置预期的场景数，含预期仅记录的正常场景。$A_{\mathrm{correct}}$ 为动作、目标、范围和授权均符合任一允许方案的场景数。 |
| 防御 | 按时阻断率 | $B_{\mathrm{timely}}/B$ | $B$ 为执行评测中应自动阻断的场景数。$B_{\mathrm{timely}}$ 为按时生效的场景数。执行回执及后续状态须共同证实目标已阻断，且 $t_{\mathrm{effect}}-t_0\leq\Delta_{\max}$。 |
| 防御 | 正常业务误拦率 | $N_{\mathrm{blocked}}/N_{\mathrm{normal,exec}}$ | $N_{\mathrm{normal,exec}}$ 为执行评测中的正常场景数。$N_{\mathrm{blocked}}$ 为其中正常流量被错误拒绝、限速或隔离的场景数。 |
| 防御 | 越权执行数 | $\sum_{i=1}^{N} u_i$ | $u_i$ 为第 $i$ 题未经授权实际执行的动作数。$u_i>0$ 时，本题处置得 0 分。 |

阻断计时从判定所需证据首次可用时刻 $t_0$ 开始。$t_{\mathrm{effect}}$ 为核验的生效时刻，$\Delta_{\max}$ 为该题允许的最长阻断耗时。比率按百分比报告，分母为零记为不适用。正确弃权、缺失输出和无效输出单独计数。

**执行评测。** 日志回放可评处置建议。验证执行效果时，在受控环境同时检查攻击流量和正常业务。例如上传检查可用测试标记文件验证按时拒绝或隔离，再用正常文件验证上传可用。登记审批或模拟回执只记录建议结果。 [首期攻击处置表](首期攻击处置表.md)

**与现有脚本的衔接。** 现有脚本按已配对且未弃权的案例计算检出率和误报率。与旧报告对比时保留原口径，正式报告列出全量指标与弃权数。算分脚本还需支持主要攻击类型匹配、等价证据组和执行回执。 [评测脚本](../../../scripts/eval_runner.py)

调查过程按关键发现给分，检测按攻击与正常场景统计，证据覆盖按已标注事实核对。 [ExCyTIn-Bench §3.2–3.3](https://arxiv.org/html/2507.14201v1#S3.SS2) · [AuditBench §4.3](https://arxiv.org/html/2606.10281#S4.SS3) · [Cyber Defense Benchmark](https://arxiv.org/abs/2604.19533)
