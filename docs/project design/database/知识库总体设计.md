# 日志安全助手知识库总体设计

## 1. 日志

| 日志类型 | 日志内容 | 获取途径 | 保存格式与数据库 | 智能体调查帮助 |
| --- | --- | --- | --- | --- |
| 网站访问与错误日志 | 接口访问信息、服务错误 | Filebeat 采集 Nginx 和应用日志 | 原始文本或 JSON 文件；解析后存入 ClickHouse | 排查扫描、注入等 Web 攻击 |
| 登录认证日志 | 账号登入情况 | Filebeat 采集网站应用和服务器认证日志 | 原始文本或 JSON 文件；解析后存入 ClickHouse | 排查密码爆破、异常登录 |
| 网络日志 | 网络连接、域名查询、HTTP 通信 | tcpdump/TShark 抓包，Zeek 解析 | 原始 PCAP 文件、Zeek JSON 日志；结构化记录存入 ClickHouse | 关联攻击链、调查可疑外连 |

网络抓包中的 **HTTPS 请求与响应采用 TLS 加密**。在支持密钥导出的采集客户端配置环境变量 `SSLKEYLOGFILE`，指定会话密钥输出文件；再将该文件配置给 Wireshark/TShark，解密对应 PCAP 中的 HTTP 内容，作为网络日志的补充。[配置说明](https://wiki.wireshark.org/TLS)

## 2. 攻击分类与防御范围

**建议以 OWASP WSTG v4.2 的安全问题分类组织 Web 知识，具体攻击作为子类。** 每类知识说明可见特征、调查证据和防御建议。[分类依据](https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/)

| 一级分类（WSTG 编号） | 代表攻击或安全问题 | 调查与防御关注点 |
| --- | --- | --- |
| 信息收集（4.1） | 目录、接口枚举，服务指纹探测 | 扫描频率、目标路径、敏感入口 |
| 配置与部署（4.2） | 备份文件暴露、危险 HTTP 方法 | 暴露资源、配置修复 |
| 身份管理（4.3） | 账号枚举、账号注册滥用 | 账号存在性泄露、注册行为 |
| 身份认证（4.4） | 密码爆破、认证绕过 | 登录失败与成功关联、账号保护 |
| [授权控制（4.5）](https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/05-Authorization_Testing/) | 目录遍历、水平或垂直越权 | 请求资源与账号权限的对应关系 |
| 会话管理（4.6） | 会话固定、会话劫持、CSRF（跨站请求伪造） | 会话来源、令牌、请求上下文 |
| [输入校验（4.7）](https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/07-Input_Validation_Testing/) | SQL／命令注入、反射型或存储型 XSS、SSRF（服务端请求伪造） | 请求输入、响应、执行结果与外连 |
| 错误处理（4.8） | 报错泄露数据库、代码或系统信息 | 错误日志与响应中的敏感信息 |
| 加密安全（4.9） | 敏感数据明文传输、TLS 配置缺陷 | 传输记录、证书和加密配置 |
| [业务逻辑（4.10）](https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/10-Business_Logic_Testing/) | 流程绕过、重复操作、恶意文件上传 | 操作顺序、使用次数、文件处理结果 |
| [客户端安全（4.11）](https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/11-Client-side_Testing/) | DOM 型 XSS、开放重定向、点击劫持 | 页面、跳转与浏览器执行证据 |

网络侧再补充 [网络服务扫描](https://attack.mitre.org/techniques/T1046/)、[命令与控制（C2）](https://attack.mitre.org/tactics/TA0011/)、[数据外传](https://attack.mitre.org/tactics/TA0010/)三类，采用 MITRE ATT&CK 的术语，关联网络记录与 Web 调查结果。

**收益：** 分类有明确出处，身份、权限、输入和业务问题各有归属，便于整理知识和追查后续攻击。
**代价：** 完整分类涉及权限、会话、浏览器和主机等证据，需按实际可获取数据确定调查深度。

结合当前三类日志，首批建议覆盖扫描、密码爆破、SQL 注入、XSS、遍历与越权、恶意上传、可疑外连；其余类别在获得对应证据后补充。

## 4. 评测方法如何用于本项目

**结论：ExCyTIn-Bench 适合作为多轮调查的主要参考；结合 AuditBench 的检测指标和 Cyber Defense Benchmark 的自主搜寻任务，形成本站判断标准。** 这是按任务匹配程度提出的选择。

### ExCyTIn 怎样判断调查能力

1. 从警报与账号、主机、IP 等实体关系构造问题，确定起始线索、目标答案和中间发现。
2. Agent 多轮查询日志数据库，依据返回记录继续调查，最后提交答案。
3. 对照标准答案判分：最终答案正确得满分；回答命中关键中间发现可得部分分。论文默认由评判模型对照答案核对，也支持明确字符串的程序比对。[§3.2–3.3](https://arxiv.org/html/2507.14201v1)

这一方法适合本项目的“查日志、关联证据、得出结论”任务。应用时，用本站 Web、认证和网络场景替换原始 Azure 场景，通过现有工具提供查询能力；补充核对结论引用的日志证据与实际处置结果。

**需要自行确定本站题目、标准答案、证据要求和处置期望；评测结构与通用指标可沿用上述研究。** 本站重点判断：

- **检测：** 攻击检出率、正常行为误报率。
- **调查：** 攻击类型、受影响账号／资产、攻击过程与影响范围是否判断正确。
- **证据：** 引用的日志是否真实存在，是否支持对应结论。
- **防御：** 处置是否符合授权、达到预期效果，以及对正常业务的影响。

答案与处置期望以受控实验结果和人工确认事实为依据。比较模型时保持日志、工具和知识条件一致。知识卡、正确案例和纠错案例继续采用现有[卡片样例](../../../design/knowledge/examples.json)的形式。
