



经过讨论，决定AI调查未预设的异常场景，但执行动作必须来自预设工具和授权范围，做一个能够主动调查、积累经验、在限定范围内处理未预设场景的安全分析 Agent。

本期使用已有大模型，通过知识库检索、案例上下文和提示词优化持续改进，模型参数保持不变。

**一、总体链路：**先完成 Agent 配置与初始化，然后 数据接入处理 → 发现线索 → 创建调查任务 → Agent 检索与多轮调查 → 结果校验 → 通知与受控响应 → 效果检查 → 保存事实与反馈 → 案例审核与经验沉淀 → 继续处理新事件；定期更新知识库、案例和提示词，经独立评测通过后发布。

**二、数据链路：**人工模拟访问、攻击或故障→ Filebeat 收集新增网站日志，PCAP文件Zeek 解析成日志 → Kafka（raw_logs）消息通道，接收原始日志并供下游消费 → Flink 解析字段、统一格式、标记异常数据 → Kafka（parsed_logs）暂存结构化日志 → ClickHouse 列式数据库保存日志，供查询和统计

**三、Agent总链路**
Agent初始化（连接已有模型、知识库和MCP工具，配置提示词、输出格式及案例示例） →发现线索 → Agent 检索与多轮调查 → 模型自检＋程序校验 → 输出诊断和计划 → 服务器权限校验 → 执行、审批或转人工 → 检查效果、调整或解除 → 保存调查与处理记录 → 案例审核 → Qdrant 建立已确认知识和案例的向量索引及元数据 → 继续处理新事件。定期修订知识库、案例和提示词 → 独立案例回归评测 → 发布或保留旧版配置。

**1、准备链路**
整理网络安全知识库 → 注册日志查询、画像查询、资产权限、PCAP 抓包文件解析和案例检索等 MCP／API 工具 → 定义结构化输入输出、工具访问范围及动作授权策略 → 准备测试数据和评测集。
**2、Agent 调查链路**
日志采集与整理 → 规则检测／行为画像偏离检查／Agent 主动巡视发现线索 → FastAPI／MCP 查询 ClickHouse 关联日志 → RAG检索安全知识和历史案例 → Agent 提出可能原因 → 调用 MCP 工具取证 → 根据返回数据继续调查 → 形成初步结论 → 结果自检与程序校验。
**3、事件处理与效果检查链路**
Agent 制定处理计划 → 服务器校验权限和影响范围 → 授权内自动执行／超出授权申请审批 → 执行器实施动作并记录 →检查结果 → Agent 判断是否需要调整 → → 保存处理记录。
**4、案例记忆链路**
保存调查与处理记录 → 根据独立证据、测试真值或人工审核标记确认状态 → 分类保存正确案例、错误案例和待确认案例 → 提炼可复用经验及纠错说明 → 为审核通过的案例建立检索索引 → 供后续 Agent 检索。
**5、知识与策略更新链路：**
汇总已确认案例、错误原因和人工反馈 → 修订知识卡、案例示例、提示词或检测规则 → 使用独立评测集与旧版对比 → 达标后发布，否则保留旧版 → 监测效果并支持回滚。评测集的标准答案不得进入 Agent 可检索的知识库或案例上下文。

**四、信息通知链路：** 产生告警、审批申请或处理结果 → 生成通知任务并保存 → 按策略选择 SMTP 邮件／钉钉 MCP → 发送摘要、证据和处理链接 → 记录发送状态 → 失败退避重试。

**五、产品迭代链路：** 汇总使用反馈、故障和评测问题 → 创建 GitHub Issue → 项目看板确定优先级、负责人和里程碑 → 分支开发并提交 PR → 自动测试与案例回归 → 代码评审 → 合并并发布版本 → 部署验收 → 保存迭代前后对照和变更记录。



**六、一些方案 **
有以下方面需要设计方案：知识库配置，Agent初始化，异常发现，自主调查，权限控制（待定），Agent记忆沉淀，案例确认与经验筛选，知识库与提示词优化，通知与迭代。
下面的这些方案是我预设方案，可以根据实际情况剔除不合理的部分，或更改更好方案：

**1、RAG 知识库方案**
根据 [OWASP](https://cheatsheetseries.owasp.org/)（Web 安全实践指南）、[MITRE ATT&CK](https://attack.mitre.org/)（真实攻击行为的分类知识库）设计模拟攻击案例，真实攻击服务器建立数据库。

| 内容               | 保存位置与用途                                        |
| ------------------ | ----------------------------------------------------- |
| 安全知识           | OWASP、MITRE、本站说明和处置手册 → Qdrant，供调查检索 |
| 原始事实           | 日志进入 ClickHouse；PCAP 保存为文件并记录引用        |
| 已确认历史案例     | 保存证据、结论、错误修订及适用条件 → 建立 Qdrant 索引 |
| 测试真值与标准答案 | 仅供评测后台读取，不能提供给被测 Agent                |

→ 使用 BGE 中文向量模型，将中文知识卡转换为表示语义的数字向量 → 存入 Qdrant。检索时，将调查问题同样向量化，RAG语义向量检索＋关键词检索 → 合并排序 → 返回知识卡和出处。[Qdrant 混合检索说明](https://qdrant.tech/documentation/search/hybrid-queries/)
**2、Agent 初始化与案例教学方案**
在恒脑中连接已有大模型、上述知识库和调查工具，配置任务目标、系统提示词、输出格式、证据要求、停止条件及操作边界；将少量已确认典型案例作为上下文示例，运行时检索相关知识与经验，完成首版 Agent 配置。
**3、异常发现方案**
Web 访问日志、认证日志统一解析、脱敏后进入 ClickHouse；PCAP（网络抓包文件）解析结果作为补充。本期复用原项目的检测规则和用户行为画像，通过规则命中、行为画像偏离检查发现线索；Agent 定时巡视补充线索。
**4、自主调查方案**
通过 FastAPI（服务器接口框架）或 MCP查询日志、用户画像、资产权限与历史案例 → 提出可能原因 → 自主选择工具补证（限制调查轮次与耗时） → 按照格式输出结论和处理建议（附带证据、未知事项）。
**5、处理和权限控制**
Agent 提交动作与证据编号 → FastAPI 验证身份和参数 → ABAC（按身份、资产、动作和条件授权）＋OPA 策略引擎 → 自动执行／进入审批／拒绝 → 执行器实施 → 检查效果、通知并到期解除
**6、Agent 记忆沉淀方案**
Qdrant 向量数据库保存长期知识与审核通过案例的向量索引及元数据；ClickHouse 列式数据库保存日志和事件事实；SQLite 轻量关系数据库记录调查、审批、执行、反馈与案例审核状态。调查结束先形成候选案例，分别确认诊断、证据和处置效果，再分类保存；错误案例检索时返回错误原因和正确修订，待确认案例暂不进入正式经验检索。
**7、案例确认与经验筛选方案**
参考微软 ExCyTIn-Bench（安全日志调查评测基准），结合本站测试案例，评估：诊断准确率、攻击召回率、证据支持率、处置正确率、正常业务影响和到期解除率。测试案例由实验真实结果判分，真实事件由人工结合证据确认，不能用模型自评分决定对错。
处理案例分为：正确案例、错误案例、待确认案例。正确案例用于经验检索和典型案例示例；错误案例保存“错误原因＋正确修订”，经审核后形成纠错知识卡；待确认案例隔离。诊断、证据、处置分别打标签。独立评测事件及其标准答案不进入 Agent 可检索的案例库。
**8、知识库与提示词优化方案**
根据已确认案例和反馈补充知识卡、案例上下文及提示词，重点改进证据要求、工具选择、停止条件和结构化输出；每次更新在固定、独立的评测集上比较诊断、证据和处置效果，达标后发布，保留旧版配置以便回滚。更新记录包含基础模型标识、知识库版本、案例版本、提示词版本和评测结果，模型参数保持不变。
**9、通知与产品迭代方案**
告警、审批申请和处置结果写入 SQLite 通知任务表 → 通过 SMTP（邮件发送协议）或钉钉发送 → 对应身份审批。问题进入 GitHub Issue／Projects → 分支开发与 PR 评审 → 自动测试和案例回归 → Release 发布，每轮保存代码、知识库、案例、提示词及基础模型标识和效果对照。

建议实施顺序：
开发顺序：先跑通原项目 → 接真实日志 → 自主调查＋知识库 → 通知和受控处置 → 案例评测与经验更新

1. **接入真实数据**：接入网站访问、登录认证日志，调整字段和检测规则；PCAP 解析作为补充。
2. **实现自主调查**：接入恒脑，让 Agent 能自己选择工具、继续查询、补充证据。原项目主要是把整理好的信息交给模型分析，这部分需要升级。[现有 AI 实现](https://github.com/Dlalmlurn/log-ai-assistant/blob/main/src/ai_engine/llm_client.py)
3. **增加知识和经验库**：整理安全知识，接入 Qdrant；保存经过确认的正确案例、错误原因和修订方法。
4. **实现受控处置**：增加权限检查、人工审批、限速／短时阻断，以及效果检查、自动解除和撤销。
5. **补齐通知和页面**：现有通知主要是 Webhook，需要增加邮件／钉钉；页面增加调查进度、审批入口和处理记录。[现有通知实现](https://github.com/Dlalmlurn/log-ai-assistant/blob/main/src/operations/notifications.py)
6. **增加案例评测与经验更新**：复用测试框架，补充调查与处置正确性检查；积累经过确认的案例，持续优化知识库、案例上下文、提示词和检测规则，并通过独立案例回归评测后发布。
