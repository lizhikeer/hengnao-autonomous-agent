## 一、约定一：Pre-flight ABAC 网关（check_action）

实现：`src/operations/response_executor.py`；回归测试：`tests/test_w3_abac_gate.py`（43 用例）。
处置受理前必须过本网关；网关只做策略预检，不产生任何处置副作用。

### 1.1 权威配置与加载

- `config/response-policy.yaml` 是**唯一权威动作枚举**（config/README.md 硬规则 1）。
  受理前先做别名归一化：`rate_limit_ip` / `throttle_ip` → `rate_limit`（以 YAML `aliases` 登记为准）。
- `config/assets.yaml` 为辅助台账：把 `target_ip` 解析成 `asset_id`，用于 `allowlist.assets` 匹配；
  不自造第二份资产枚举（config/README.md 硬规则 2）。
- `SECLOG_CONFIG_DIR` 可覆盖配置目录（与 `src/api/asset_context.py` 同一约定）；
  策略按文件 mtime 缓存，改配置即生效；`reset_cache()` 供测试隔离。
- **fail-closed**：策略或台账缺失 / 解析失败 / 结构非法时，不放行、不抛异常，
  返回 `policy_unavailable`；动作未声明 `requires_evidence` 时按"需要证据"处理。

### 1.2 接口契约

```python
check_action(action, target_type, target_ip, target_user, evidence_log_ids) -> (allowed, policy_reason)
```

| 参数 | 说明 |
| :--- | :--- |
| `action` | 处置动作名，支持 YAML 登记的别名（受理前归一化） |
| `target_type` | 目标资产类型（`web` / `host` / `database` / ...，取值见 assets.yaml） |
| `target_ip` | 目标 IP：白名单 ips 直接比对；assets 经台账解析成 asset_id |
| `target_user` | 涉事账号：白名单 users 通配匹配（如 `ops_*`） |
| `evidence_log_ids` | 证据日志 ID 列表（兼容逗号 / 分号分隔字符串） |

返回：放行 `(True, "ALLOWED")`；拦截 `(False, "BLOCKED_BY_POLICY:<code>:<细节>")`。

> **`allowed=True` 仅代表策略预检通过、可以受理。**
> `auto_execute: false` 的高危动作仍须下游审批层放行，本网关不代替审批。

### 1.3 判定顺序（先命中先返回，保证原因可解释）

1. 策略可用性（fail-closed）
2. 别名归一化
3. `forbidden_actions` 硬拦截（不在枚举里也先按"禁止"定性，而不是"未知"）
4. 权威枚举外动作拒绝
5. `allowlist`（ips → assets → users，按条目 scope 匹配动作）
6. `target_types` 越界
7. `requires_evidence` 证据门槛

### 1.4 拦截原因码

| code | 触发条件 |
| :--- | :--- |
| `policy_unavailable` | 策略 / 台账缺失或非法（fail-closed） |
| `forbidden_action` | 命中 `forbidden_actions`（永远不执行，只能转人工） |
| `unknown_action` | 动作未在权威枚举登记（含空动作名） |
| `allowlist_ip` | `target_ip` 命中 `allowlist.ips` 且动作在该条目 scope 内 |
| `allowlist_asset` | `target_ip` 经台账解析出的资产命中 `allowlist.assets` 且动作在 scope 内 |
| `allowlist_user` | `target_user` 命中 `allowlist.users`（`fnmatchcase` 通配）且动作在 scope 内 |
| `target_type_not_allowed` | `target_type` 不在动作 `target_types` 内（含缺失 target_type） |
| `missing_evidence` | 动作 `requires_evidence: true` 而 `evidence_log_ids` 为空 |

### 1.5 证据约定（missing_evidence）

- 证据要求按 YAML 的 `requires_evidence` **逐动作**执行；`none` 为 `false`，故 `none` 无证据也放行。
- 空证据包括 `None`、`[]`、全空白项；命中拦截时 `policy_reason` **必须含 `missing_evidence`**。

### 1.6 白名单约定

- 语义：命中的源**不进入自动处置**（保护性拦截），上游仍生成线索供人判断。
- `scope` 决定条目覆盖哪些动作：`全部动作`（或未写 scope）覆盖所有动作；
  列表只覆盖列出的动作；**scope 之外的动作不享受该条豁免**。
- 账号通配用 `fnmatchcase`（大小写敏感）；IP 为精确字符串匹配。
- 当前登记快照（**权威以 YAML 为准**，改 YAML 不需要改本表，但语义变更须修订本规范）：

| 节 | 条目 | scope |
| :--- | :--- | :--- |
| ips | `10.0.0.40`（备份主机） | 全部动作 |
| ips | `127.0.0.1`（本机回环） | 全部动作 |
| ips | `10.0.0.77`（授权扫描器） | `block_ip` / `block_ip_short_term` / `rate_limit` |
| assets | `db-core-01`（核心数据库，台账 IP `10.0.0.30`） | `block_ip` / `block_ip_short_term` |
| users | `ops_*` / `ops`（运维账号） | `isolate_account` |

### 1.7 target_types 约定

- `block_ip` **仅允许 web 资产**；其余动作按 YAML（`block_ip_short_term` / `rate_limit` / `isolate_account`：web + host）。
- `target_types` 为空（`none`）表示无资产副作用，跳过类型校验；
  其余动作缺失 `target_type` 一律拒绝（无法核验目标就谈不上授权）。

## 二、约定二：审计日志字段顺序

### 2.1 冻结顺序（2026-11-17 确认）

响应执行器的审计记录按以下**固定字段顺序**输出，以后一律照此执行：

```text
ts, action, target_type, target, evidence_log_ids, policy_reason
```

### 2.2 字段说明

| # | 字段 | 说明 | 与网关契约的对齐 |
| :-: | :--- | :--- | :--- |
| 1 | `ts` | 审计时间戳 | 格式未由本约定冻结；建议与统一 Schema 的 ISO 8601 时间格式对齐（见《全链路日志统一字段规范》§2 `timestamp`） |
| 2 | `action` | 处置动作 | 对应 `check_action` 的 `action` 入参 |
| 3 | `target_type` | 目标资产类型 | 对应 `check_action` 的 `target_type` 入参（取值见 assets.yaml） |
| 4 | `target` | 处置目标标识 | 网关入参为 `target_ip` / `target_user`；单一 `target` 字段的取值细则未由本约定冻结，由执行层按动作细化，并保持与网关入参可追溯 |
| 5 | `evidence_log_ids` | 证据日志 ID 列表 | 对应 `check_action` 的 `evidence_log_ids` 入参 |
| 6 | `policy_reason` | 策略预检原因 | 原样记录 `check_action` 返回的第二个值（`ALLOWED` 或 `BLOCKED_BY_POLICY:<code>:<细节>`） |

### 2.3 实现边界

- **审计落盘由下游执行 / 状态机层实现**；网关层（PR #37）不写审计文件。
- 本约定约束响应执行器后续所有审计输出；存储介质与序列化格式由执行层确定，
  但**字段名与顺序不得私自更改**，变更须先修订本规范。
