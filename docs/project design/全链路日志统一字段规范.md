## 一、为什么需要这份规范

三类日志各有各的字段体系：Nginx 是空格分隔的文本行，`auth.log` 是 syslog 自由文本，Zeek 是带 `#fields` 表头的 TSV。如果不先约定统一出口，后续会出现三个问题：

1. **Agent 无法串联攻击链**——同一攻击者在 Web 日志里叫 `remote_addr`，在 Zeek 里叫 `id.orig_h`，工具层得为每种源写一套查询；
2. **检测规则无法复用**——老项目的 `RuleEngine` 按 `src_ip` / `user_id` / `action` 聚合，字段一对不上就要重写规则；
3. **评测无法给证据编号**——没有稳定的 `log_id`，Agent 输出的 `evidence_log_ids` 就无法做真实性校验。

因此约定：**上游随便什么格式，落库前必须折叠成本规范定义的 18 个契约字段。**

## 二、契约字段字典

所有清洗产物为 **JSON Lines**（一行一个 JSON 对象），UTF-8 无 BOM。

| # | 字段 | 类型 | 必填 | 说明 | 取值 / 格式 |
| :-: | :--- | :--- | :-: | :--- | :--- |
| 1 | `log_id` | string | ✅ | 全局唯一日志编号，证据引用与校验的唯一锚点 | `LOG-YYYYMMDD-NNNN`，见 §4.1 |
| 2 | `trace_id` | string | ✅ | 攻击故事链 / 调查链标识，同一链所有日志共享 | `CHAIN-<三位序号>` 或 `INV-<调查ID>`；无链时填 `""` |
| 3 | `timestamp` | string | ✅ | 事件发生时间，**统一 UTC** | ISO 8601 `2026-10-27T14:20:05.123Z` |
| 4 | `log_source` | string | ✅ | 日志来源类型 | 见 §3.1 枚举 |
| 5 | `src_ip` | string | ✅ | 源 IP（攻击者/发起方） | IPv4 / IPv6 点分文本；未知填 `""` |
| 6 | `src_port` | int \| null | ⬜ | 源端口 | `0-65535`；未知填 `null` |
| 7 | `dest_ip` | string | ✅ | 目的 IP（被访问资产） | 同上 |
| 8 | `dest_port` | int \| null | ⬜ | 目的端口 | `0-65535`；未知填 `null` |
| 9 | `asset_id` | string | ✅ | 被访问资产标识，与资产台账对齐 | `web-prod-01`、`db-core-01`；无法判定填 `unknown` |
| 10 | `user` | string | ⬜ | 关联账号；无账号语义时填 `""` | 已脱敏的账号名，禁止填明文口令 |
| 11 | `session_id` | string | ⬜ | 会话标识，用于把同一会话的多条日志折叠 | 优先取应用层 Session；无则 `""` |
| 12 | `action_or_method` | string | ✅ | 行为动词：HTTP 方法 / 认证动作 / 协议服务 | `GET`/`POST`/`login`/`logout`/`connect`/`ssh` |
| 13 | `uri_or_target` | string | ⬜ | Web 日志填 URI（含 query）；网络日志填 `host:port`；认证日志填 `sshd` 等服务名 | `/admin/login.php?x=1` |
| 14 | `payload_summary` | string | ⬜ | **已脱敏**的请求体 / 参数摘要，是攻击特征的主要载体 | 见 §4.3 脱敏规则 |
| 15 | `status_code` | int \| null | ⬜ | HTTP 状态码 / 认证结果码 | `200`/`401`/`404`；认证成功 `0`，失败 `401` |
| 16 | `bytes_out` | int \| null | ⬜ | 服务端响应字节数（下行），用于判断数据外泄 | `0` 及以上 |
| 17 | `user_agent` | string | ⬜ | 客户端 UA，工具特征识别的主要依据 | 原始 UA，超长截断至 512 字符 |
| 18 | `attack_stage_hint` | string | ✅ | 攻击阶段提示，规则/人工标注均可 | 见 §3.2 枚举；无法判定填 `unknown` |

> **工程字段（契约之外，落库时附加，不参与 Agent 输出校验）**：
> `ingest_time`（入库时间）、`source_file`（来源文件名）、`raw_log`（原始日志行，取证用）。

## 三、枚举定义

### 3.1 `log_source`

| 值 | 含义 | 典型来源 |
| :--- | :--- | :--- |
| `nginx_access` | Web 访问日志 | Nginx / Caddy access log |
| `auth_log` | 认证日志 | `/var/log/auth.log`、Web 登录接口日志 |
| `zeek_conn` | 网络连接流日志 | Zeek `conn.log` |
| `zeek_http` | 网络层 HTTP 日志 | Zeek `http.log` |
| `zeek_dns` | DNS 查询日志 | Zeek `dns.log` |

新增来源必须先在本表登记，并在 `sql/clickhouse/06_full_chain_logs.sql` 的列注释中同步。

### 3.2 `attack_stage_hint`

| 值 | 含义 | 判据示例 |
| :--- | :--- | :--- |
| `recon` | 侦察 / 扫描探测 | 短时间大量 404、扫描器 UA、敏感路径探测 |
| `brute_force` | 认证爆破 | 同一 `src_ip` 对登录接口连续失败 |
| `exploitation` | 漏洞利用 | SQLi / XSS / 上传 payload 命中，或利用后返回 200 |
| `c2_callback` | 外连回连 | 内网资产向未知外部 IP 发起长连接或心跳 |
| `lateral_movement` | 横向移动 | 内网资产之间的异常认证 / SMB / RDP 连接 |
| `benign` | 正常业务 | 已确认为合法访问 |
| `unknown` | 未判定 | 规则未命中且未经人工标注 |

**约定**：`attack_stage_hint` 是**提示**不是结论。Agent 可以推翻它，但必须在 `unknown_items` 里说明理由。

## 四、生成规则

### 4.1 `log_id` 生成

必须**确定性**生成，保证同一输入重复清洗得到同一编号（幂等）：

```
log_id = "LOG-" + YYYYMMDD(timestamp, UTC) + "-" + 4 位序号
序号 = (源文件内该日期的行序) % 10000，左补零
```

禁止使用随机数或入库自增 ID——否则重跑清洗脚本会导致证据编号漂移，Agent 历史输出的 `evidence_log_ids` 全部失效。

### 4.2 时间处理

- 原始日志的本地时间（如 Nginx 的 `+0800`）**必须转成 UTC**；
- 精度保留到毫秒，不足补 `0`；
- 缺失时区信息的日志，按 `Asia/Shanghai` 解释后转 UTC，并在 `raw_log` 保留原文以便复核。

### 4.3 脱敏规则（`payload_summary`）

按顺序执行：

| 目标 | 处理 |
| :--- | :--- |
| `password=` / `passwd=` / `pwd=` 的值 | 替换为 `***` |
| `Cookie` / `Authorization` / `token` 的值 | 替换为 `***` |
| 身份证号（18 位）、手机号（11 位） | 替换为 `***` |
| 请求体超过 512 字符 | 截断并追加 `...[truncated]` |

**保留**攻击特征字符串（`UNION SELECT`、`' OR 1=1--`、`<script>`、`../`），这些是检测依据，**不得脱敏**。

## 五、三源字段映射表

### 5.1 Nginx access（combined）

原始格式：

```
$remote_addr - $remote_user [$time_local] "$request" $status $body_bytes_sent "$http_referer" "$http_user_agent"
```

| 统一字段 | 来源 | 转换 |
| :--- | :--- | :--- |
| `src_ip` | `$remote_addr` | 直取 |
| `user` | `$remote_user` | `-` → `""` |
| `timestamp` | `$time_local` | `27/Oct/2026:14:20:05 +0800` → UTC ISO8601 |
| `action_or_method` | `$request` 第一段 | 直取 |
| `uri_or_target` | `$request` 第二段 | 直取（含 query） |
| `status_code` | `$status` | 转 int |
| `bytes_out` | `$body_bytes_sent` | 转 int |
| `user_agent` | `$http_user_agent` | 直取，超 512 截断 |
| `payload_summary` | 请求体 | Nginx 默认不记录 body，需 `$request_body`；缺失时填 `""`，从 URI query 提取 |
| `dest_ip` / `dest_port` | 站点配置 | 由 `asset_id` 台账反查，或填容器/宿主 IP |
| `asset_id` | 站点配置 | 按 `server_name` / 端口映射到资产台账 |
| `session_id` | Cookie / 响应 Token | 从 `payload_summary` 或 Cookie 提取 |

### 5.2 auth.log（Debian sshd）

原始格式：

```
Nov  1 23:52:01 kekeshenla sshd[1234]: Failed password for invalid user admin from 198.51.100.23 port 54321 ssh2
```

| 统一字段 | 来源 | 转换 |
| :--- | :--- | :--- |
| `timestamp` | 行首时间 | 无年份，按日志文件年份补全，本地时区 → UTC |
| `log_source` | 固定 | `auth_log` |
| `src_ip` | `from <ip>` | 正则提取 |
| `src_port` | `port <n>` | 正则提取 |
| `dest_ip` / `dest_port` | 固定 | 本机管理 IP / `22` |
| `user` | `for (invalid user )?<name>` | 正则提取，`invalid user` 前缀去掉 |
| `action_or_method` | 固定 | `ssh` |
| `uri_or_target` | 固定 | `sshd` |
| `status_code` | 关键字 | `Accepted` → `0`；`Failed`/`Invalid` → `401` |
| `attack_stage_hint` | 关键字 + 频次 | `Failed` 连续 ≥5 次 → `brute_force`，否则 `benign` |
| `asset_id` | 主机名 | `kekeshenla` → `nas-host-01` |

Web 登录日志（应用侧）映射同理，`action_or_method` 取 `login` / `logout`。

### 5.3 Zeek conn.log

Zeek TSV 以 `#fields` 声明列名，**必须按表头解析，不得按列序号硬编码**。

| 统一字段 | Zeek 字段 |
| :--- | :--- |
| `timestamp` | `ts`（epoch 秒，浮点）→ UTC ISO8601 |
| `src_ip` | `id.orig_h` |
| `src_port` | `id.orig_p` |
| `dest_ip` | `id.resp_h` |
| `dest_port` | `id.resp_p` |
| `action_or_method` | `proto`（`tcp`/`udp`）或 `service` 非空时优先取 `service` |
| `uri_or_target` | `<id.resp_h>:<id.resp_p>` |
| `bytes_out` | `resp_bytes`（服务端下行） |
| `status_code` | `conn_state` 映射：`SF`→`200`，`REJ`/`S0`→`null` |
| `payload_summary` | `conn_state` + `history` 摘要，如 `SF/ShADadFf` |
| `log_source` | 固定 `zeek_conn` |
| `attack_stage_hint` | `benign`（连接层无攻击语义，由上层关联判定） |

### 5.4 Zeek http.log

| 统一字段 | Zeek 字段 |
| :--- | :--- |
| `timestamp` | `ts` |
| `src_ip` / `src_port` | `id.orig_h` / `id.orig_p` |
| `dest_ip` / `dest_port` | `id.resp_h` / `id.resp_p` |
| `action_or_method` | `method` |
| `uri_or_target` | `host` + `uri` 拼接 |
| `status_code` | `status_code` |
| `bytes_out` | `response_body_len` |
| `user_agent` | `user_agent` |
| `payload_summary` | `username` / `password` 字段脱敏后拼接；无则 `""` |
| `user` | `username`（脱敏后） |
| `log_source` | 固定 `zeek_http` |

### 5.5 Zeek dns.log

| 统一字段 | Zeek 字段 |
| :--- | :--- |
| `uri_or_target` | `query`（查询域名） |
| `action_or_method` | `qtype_name`（`A`/`AAAA`/`TXT`…） |
| `status_code` | `rcode_name` 为 `NOERROR` → `200`，否则 `null` |
| `payload_summary` | `answers` 拼接 |
| `log_source` | 固定 `zeek_dns` |

## 六、落库映射

统一 Schema 落 `log_ai.full_chain_logs`（见 `sql/clickhouse/06_full_chain_logs.sql`），两处命名差异：

| JSON 契约字段 | ClickHouse 列 | 原因 |
| :--- | :--- | :--- |
| `user` | `user_name` | `user` 与 ClickHouse 内置函数同名，直接作列名会在查询时产生歧义 |
| `timestamp` | `timestamp` | 保持一致；注意这是 CH 关键字外可用标识符，查询需加反引号 |

其余字段一一对应。`payload_summary` 落库前必须过 §4.3 脱敏，**禁止落库明文口令**。

## 七、校验清单（清洗脚本 PR 必查）
