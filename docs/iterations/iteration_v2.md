## 3.3 根因定位分析

| 根因层级 | V1 定位结论 | V2 对应修复 |
| --- | --- | --- |
| 知识检索与主分类 | 检索不可用，多阶段行为同时命中时主链选择不稳定 | 混合检索返回知识卡，按卡片步骤补查并保留 `cards_used` / `card_triggered_queries` |
| 证据计划 | 只截取显著片段，缺少影响与闭环阶段 | 引入 `evidence_plan`，区分 attack、impact、post_compromise、authorized_scan、benign_retry_pattern 等证据组 |
| 授权与恶意判定耦合 | 无法证明正常就直接弃权，忽略失败转成功、周期外连等行为证据 | 行为规则优先识别攻击成立条件；正常重试按低频失败、同源成功和后续业务判据独立分流 |
| 正常来源归因 | 正常结论统一写 `unknown`，丢失已确认来源 | 输出实际运维、扫描或办公网来源，使判定、IP、资产和类型四要素一致 |
| 处置目标约束 | 弃权导致动作缺失，host 场景的封禁时长未进入结论 | CASE-06 按资产类型选择短时封禁，高危动作继续要求人工审批 |
| 评分器兼容性 | 连续大写缩写被拆字，历史 V1 诊断分偏低 | 保留完整缩写，并兼容历史正常活动标签；该修复不计入 Agent 行为收益 |

- 平台、NAS ClickHouse 和公网 HTTPS 联调仍待执行；后续结果必须另存为 `platform` 来源并重新出分。
