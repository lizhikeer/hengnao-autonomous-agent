## 三、网络拓扑与链路

### 3.1 完整链路（当前生效）

```
恒脑 SaaS 云端
  │  HTTPS（Let's Encrypt，TLS 1.2/1.3，证书 SAN 精确匹配）
  ▼
https://seclog.91666.icu:18443
  │  DNS：seclog.91666.icu → A → 跟随 9188888.cn（每 5 分钟 cron 同步）
  │  当前解析值：125.112.2.201（2026-11-23 观测，会变）
  ▼
中转机 9188888.cn:18443（frps 按端口转发）
  │  frps 仅在 frpc 注册成功后才监听 18443；控制端口 7000
  ▼
NAS frpc-seclog.service（systemd，Restart=always）
  │  serverAddr 必须写域名 9188888.cn，写死 IP 会在家宽换 IP 后永久 SYN-SENT
  │  本地转发到 127.0.0.1:18443
  ▼
seclog-caddy（容器，host 网络，只 bind 127.0.0.1）
  │  TLS 在此终止，反向代理
  ▼
seclog-api（容器）127.0.0.1:18000
  │
  ├─► seclog-clickhouse  127.0.0.1:8123 / 9000
  └─► seclog-qdrant      127.0.0.1:6333 / 6334
```

### 3.2 为什么用 `seclog.91666.icu` 而不是中转机自己的 DDNS 域名

证书签在 `seclog.91666.icu` 上，换域名等于换证书。而中转机是家宽动态 IP，如果直接把 A 记录写死，IP 一变就断。

解决方式是 **A 记录跟随**（不是 CNAME）：

```
cron（每 5 分钟）
  → 解析 9188888.cn 的 A 记录
  → 与 seclog.91666.icu 当前 A 记录比对
  → 不一致则调 DNSPod API 更新
```

脚本：`scripts/ops/ddns_sync.py`，凭据复用 acme.sh 已存的 DNSPod token。

**不用 CNAME 的原因**：证书续期走 acme.sh 的 `dns_dp`（DNS-01），需要在 `_acme-challenge.seclog.91666.icu` 建 TXT 记录；父节点是 CNAME 时部分递归解析器会拒绝解析其子域，等于拿「IP 跟随」换「续期失败」。

### 3.3 HTTPS 证书

| 项 | 值 |
| :--- | :--- |
| 签发 | Let's Encrypt ECC，CN=`seclog.91666.icu` |
| 有效期 | 2026-11-12 → 2027-02-10 |
| 续期 | `acme.sh --cron`，每天 03:59 / 09:59 / 15:59 / 21:59，`dns_dp` 方式 |
| 证书路径 | `/etc/caddy-seclog/certs/seclog.91666.icu.{pem,key}`（宿主，600） |
| 加载方式 | Caddyfile 里 `tls` 指令手动指定，**Caddy 不做 ACME** |

续期后需要让 Caddy 重新加载证书，否则仍在用旧的。续期 hook 目前未挂，属于遗留项（见 §9）。

## 九、故障排查

### 9.1 平台报"网络不可达"

按顺序查：

1. **DNS**：`dig +short A seclog.91666.icu` 与 `dig +short A 9188888.cn` 应返回**同一个**中转机当前 IP
2. **中转机控制端口**：`nc -z 9188888.cn 7000`（ICMP 大概率被禁，别用 ping 判断）
3. **隧道**：`systemctl status frpc-seclog`，日志里应有 `start proxy success`；`ss -tn state established | grep 9188888` 应有连接
4. **中转入口端口**：`nc -z 9188888.cn 18443`。**注意**：frps 只在 frpc 注册成功后才监听 `remotePort`，所以第 3 步失败时这一步必然失败，不要反过来当成"朋友端口没开"
5. **本地 Caddy**：`curl --resolve seclog.91666.icu:18443:127.0.0.1 https://seclog.91666.icu:18443/health`（**必须带 SNI**，直接打 `127.0.0.1` 会因 SNI 不匹配报 `TLSV1_ALERT_INTERNAL_ERROR` 或 000，这不代表 Caddy 坏了）
6. **后端**：`curl -sS http://127.0.0.1:18000/health`

### 9.1.1 家宽换 IP 导致全链路掉线（2026-11-23 发生，当日已修复）

**症状**：平台报网络不可达；`seclog.91666.icu:18443` 连接超时；但 `9188888.cn:7000` 通、NAS 本地 18443 健康检查 200、证书正常。

**根因**：朋友家宽 IPv4 从 `125.112.0.13` 变更为 `125.112.2.201`。DDNS 已把 `9188888.cn`/`seclog.91666.icu` 更新到新 IP，但 `frpc-seclog.service` 的 `serverAddr` **硬编码了旧 IP**，于是永远 `SYN-SENT`，frps 侧无客户端注册 → `remotePort 18443` 不监听。

**确认命令**：
```bash
ss -tnp | grep frpc          # 看到 SYN-SENT 到旧 IP 即确诊
dig +short A seclog.91666.icu
dig +short A 9188888.cn
```

**修复路径 A（常规，有 sudo 密码）**——一次性把 IP 换成域名，此后永久免疫换 IP：
```bash
sudo sed -i.bak 's/125\.112\.0\.13/9188888.cn/g' /etc/frp/frpc-seclog.toml
sudo systemctl restart frpc-seclog.service
ss -tn state established | grep 9188888   # 应出现 ESTAB
curl -sS https://seclog.91666.icu:18443/health   # 应 200
```

**修复路径 B（本机 sudo 密码失效时，2026-11-23 实际采用）**——该机 sudoers 显式配了 `NOPASSWD: /usr/bin/docker`，且 `lzk` 在 `docker` 组，可用容器以 root 身份改配置：
```bash
# 1) 备份 + 改地址 + 校验
sudo -n docker run --rm --entrypoint sh -v /etc/frp:/etc/frp caddy:2-alpine -c \
  'cd /etc/frp && cp -p frpc-seclog.toml frpc-seclog.toml.bak.$(date +%Y%m%d) \
   && sed -i "s/125\.112\.0\.13/9188888.cn/g" frpc-seclog.toml \
   && grep -n "^serverAddr" frpc-seclog.toml'

# 2) 重启：给宿主命名空间里的 frpc 发 TERM，systemd 的 Restart=always 会自动拉起
sudo -n docker run --rm --privileged --pid=host --entrypoint sh caddy:2-alpine -c \
  'for p in $(pidof frpc); do kill -TERM $p; done'
```

> ⚠️ 用 `sed -i` 改完务必确认属主仍是 `frpc:frpc` + 权限 `600`，否则 frpc 读不到配置。
> ⚠️ **不要**用 `docker rm -f seclog-frpc` 与上面的 `pidof frpc` 混用——历史遗留的 `seclog-frpc` 容器（natfrp 时代）里也跑着 `frpc` 进程，会误杀。清理时先删容器再 kill。

- 过期就手动续期（§8.3）并重启 Caddy

### 9.3 全家桶都正常但平台调不通

平台侧可能没配端口或配了错误路径。当前平台已实测接受 `18443`；MCP 必须 `/mcp/`。

## 十、已知限制

| 限制 | 影响 | 缓解 |
| :--- | :--- | :--- |
| 中转机是朋友的、家宽 | 单点依赖；对方下线/换机即断；上行带宽有限 | DDNS + 定期检查；W3 评估自建 |
| 非标端口 18443 | 平台策略若收紧需改 443 | 改为 443 需朋友的 frps 做 SNI 分流，成本高 |
| NAS 仅 7.7 G 内存 | 服务多了会 OOM | 各容器已设内存上限，加服务前先看 `docker stats` |
| 宿主机无 pydantic | 运维脚本必须跑在容器里 | 见 §8.2 |
| 证书续期无 hook | 续期后不自动 reload，可能仍用旧证书 | 待补 hook（`--reloadcmd "docker restart seclog-caddy"`） |
| `seclog-frpc` 容器仍在 `restarting` | 是 natfrp 时代的废弃容器（`nginx:alpine` 镜像跑 `frpc -f <token>`，无端口映射），每几秒崩一次，刷 journal 且占用 natfrp 名额 | **可直接下线**：`docker rm -f seclog-frpc`；主链路走 systemd 的 `frpc-seclog`，与它无关 |
| 明文 18000 | —— | **已关闭**，仅本地可达 |
