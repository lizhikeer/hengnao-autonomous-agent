## 三、已选选题：SecLog-Agent

### 3.1 选题定位

**面向 SOC 运营的日志智能研判与响应编排智能体（SecLog-Agent）**

- **目标用户**：SOC 一线安全分析师（L1）、企事业单位安全运维工程师
- **核心痛点**：告警疲劳——海量日志噪声淹没有效告警，人工研判耗时长、经验难沉淀
- **系统边界**：支持 Web 访问日志 / 网络遥测日志 / 主机认证日志 / WAF 告警日志的单条与批量研判；**不做**底层二进制流量组包还原，**不做**无审批的全自动高危处置

### 3.2 三层架构

```
编排层：恒脑智能体平台（云端 SaaS）
  └─ 开始 → 代码清洗 → 分流路由 → LLM研判(+RAG) → HTTP检索 → 结果组装
     → 邮件通知 → 交互节点(人工确认) → 处置执行 → 结束
                        │ HTTPS（IPv4，natfrp 穿透）
工具层：NAS FastAPI 适配层（Docker + Caddy）
  └─ /api/tools/ip_summary · ip_recent_alerts · ip_enrich · whitelist_check
     /notify_email · /api/response/block_ip
                        │ 内网
数据层：NAS ClickHouse
  └─ 明细表 network_events + 源IP小时级物化视图
     Brimcap/Zeek 离线解析 · CIC-IDS2017 转换 · 仿真数据生成
```

### 3.3 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 流程编排方式 | **显式确定性 DAG**，不用自规划节点 | 安全处置流程必须确定性路由；自规划节点行为不可控且要求模型上下文 ≥128K |
| 数据库交互 | **强类型参数化 API**，不做 Text-to-SQL | 防 SQL 方言错误、全表扫描 OOM、越权注入 |
| 日志接入位置 | **NAS/ClickHouse 侧先完成接入、切片、去重** | 恒脑不是日志接入引擎，避免 Token 溢出与长连接超时 |
| 白名单/资产上下文 | **不写死在提示词**，由 FastAPI 配置中心统一提供并审计 | 便于变更留痕与全局管控 |
| 高危处置 | **交互节点人工确认 + HMAC 门禁 + 硬白名单**三重防线 | 防误杀核心资产导致业务中断 |
| 模型策略 | V0 先用**平台内置模型**跑通，后切自定义 DeepSeek | 避免开题期引入网络不确定性 |
| 编排维护方式 | **脚本生成完整 JSON → 导入平台 → 界面微调** | 拖拽仅是可视化方式，JSON 支持版本管理与协作 |

### 3.4 已知的平台硬约束

- 恒脑云端出口**不支持 IPv6**（已实测：`dial tcp [240e:...]:8443: connect: network is unreachable`）→ 工具层必须走 **natfrp 穿透到 IPv4**；
- API 工具必须**先在平台调试返回 HTTP 200**，否则节点置灰不可选；
- 智能体必须**发布**后才有 `agent_id`；
- **Guided JSON** 的 `required` 列表禁止为空；
- 研判节点 **Temperature ≤ 0.2**；
- 知识库单库 ≤ 20 文件，单文件 ≤ 100 MB；
- 交互节点命名仅限字母数字下划线，首字符非数字；
- 全链路（LLM + RAG + ClickHouse + SMTP）耗时预计 10 ~ 30s。

### 3.5 三轮迭代规划

| 迭代 | 优化类别 | 核心问题 | 修改内容 |
|---|---|---|---|
| V0 | — | 单 LLM 节点极简拓扑 | 跑通基线，暴露缺陷 |
| V0→V1 | A 提示词 + D 格式约束 | 二次编码载荷漏报；输出格式漂移 | CoT 三段式 + Few-Shot + Guided JSON |
| V1→V2 | B 业务流程 | 残缺日志幻觉编造；无害流量空耗 | 前置清洗节点 + 条件分支 + ClickHouse 检索打通 |
| V2→V3 | C 技能工具 + 知识库 | 无外部情报上下文；建议泛化 | 情报代理 + RAG + 邮件通知 + 人工确认阻断 |

### 3.6 落地顺序

```
V0：日志清洗 + LLM 研判 + Guided JSON 输出（平台内置模型）
V1：白名单/残缺/可疑条件分支，完善提示词与评测集
V2：接入 ClickHouse 历史画像和证据检索插件（打通 IPv4 链路）
V3：邮件通知、人工确认、阻断执行、OpenAPI 消费
```

## 四、请你完成的任务

### 任务 1：架构评审（Critical Review）

逐项审查上述设计，重点回答：

1. **架构合理性**：三层架构的职责划分是否有重叠或缺口？恒脑编排层与 NAS 工具层的边界是否恰当？
2. **可行性风险**：10 周周期内，哪一环节最可能成为瓶颈？IPv6/natfrp 链路是否还有未识别的隐患？
3. **平台适配**：设计是否充分用到了恒脑的能力（工作流节点、知识库、条件分支、人工确认、结构化输出）？是否遗漏了平台的关键特性？
4. **优化留痕**：三轮迭代的规划是否满足"每轮写清五点"的铁律？优化维度是否至少覆盖 A/B/C 中的两类？
5. **答辩稳定性**：现场演示"2 正常 + 1 异常"的路径是否存在依赖外部网络的脆弱点？

### 任务 2：设计补强（Design Enhancement）

请补充或修正以下内容：

1. **工作流节点配置**：给出完整的节点清单（含每个节点的输入/输出参数、变量引用语法）；
2. **系统提示词**：撰写一份可直接使用的 CoT 研判提示词（含角色设定、推理阶段、输出 Schema 约束、提示词注入防御条款）；
3. **测试案例集**：设计 8 个以上用例，明确标注哪 3 个用于现场答辩演示，并说明每个用例的期望输出；
4. **编排 JSON 规范**：说明符合平台导入规范的 JSON 应包含哪些必需字段（节点、边、参数、条件、插件真实 ID），以及导入前应校验什么；
5. **异常兜底设计**：列出所有可能的外部依赖故障点及对应的降级策略。

### 任务 3：风险清单（Risk Register）

以表格形式输出风险登记表：风险项 / 等级 / 影响 / 应对措施 / 责任周次。

### 任务 4：10 周执行计划（Week-by-Week）

按周细化任务，标注每周末的验收物与责任分工建议。

### 任务 5：交付物模板

为"优化过程记录"和"测试案例集"设计可复用的表格模板，确保符合课题验收要求。
